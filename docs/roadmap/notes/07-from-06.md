# Milestone 07 notes, from closing Milestone 06

**Written:** 2026-11-22, closing Milestone 06  
**Use when:** starting viewer participation

## What the world already does

A living character picks one action from the scored definitions in
`packages/simulation/src/systems/actions.ts`. The catalog runs through
`buy`. Commitment is five seconds. An urgent need at 0.8 interrupts and
cools the cut-off action for 20 seconds. Finishing a meal, drink, rest,
or visit does not cool it.

The log, memories, and relationships are one record per fact. Live
queries read indexes built when the record is written. The live log
keeps the newest 10,000 events. Events that fall off wait on
`pendingLog` until the server confirms the save, then
`acknowledgePendingLog` drops them. SQLite keeps the newest 100,000 of
those same events (`SIMSAND_LOG_RETENTION`). Inspection history is the
stored rows plus the live window. Schema version is 2. A version 1
database gains the event tables on open. Saves are still format version
23. Restart resumes at the saved tick. Downtime is not simulated.

`CommandGateway` validates `character.create` and `character.remove`.
The server sets the issuer. Viewers are allowed no commands. Admin,
streamer, and system may create and remove. The simulation applies a
valid command and returns `character.created` or `character.removed` on
the result. Nothing in the running server calls the gateway. There is
no public route, no Twitch connection, no rate limit, and no
deduplication. Those domain events are not the character log, and they
are not written to `simulation_events`.

Characters in the world are seeded NPCs. A character record has no
viewer id. `docs/architecture/viewer-identity.md` is still a draft.

Regression for Milestones 03, 04, 05, and 06 is in
`packages/simulation/src/regression.test.ts`. The retained log, the
schema migration, and backup are covered in
`apps/server/src/world-store.test.ts`.

## What Milestone 07 will find in the way

1. **The gateway is the command boundary that already exists.** Do not
   add a second parser. A viewer command has to become a
   `SimulationCommand` whose issuer the server chose. The request must
   not be able to name its own issuer.

2. **Viewers are refused today.** `PERMISSIONS.viewer` is empty. The
   first viewer command needs a permission change and a reason. Creating
   their character is the reason already named in the milestone. Do not
   hand viewers `character.remove` just because admin has it.

3. **A character id is the world's id.** Create already rejects an id
   that exists and a position outside the map. A viewer needs a stable
   id that survives a platform rename. The platform user id is not that
   character id.

4. **The character log is not a command receipt.** Greetings, gifts,
   and trades are already retained. `character.created` is a different
   record. Leave it on the command result until a viewer needs that
   receipt after the response is gone. Do not write it into
   `simulation_events` under a new shape.

5. **Nothing catches the world up after a restart.** A viewer who
   arrives later finds the saved tick. Do not simulate the gap so their
   character has been eating while the process was stopped.

6. **Catalogs are append-only, and component arrays are process-global.**
   A second `createSimulationWorld` in the same test overwrites the
   first world's slots. Save format 23 has no viewer field. Adding one
   is the next version.

## Suggested first increment

One viewer, identified by the server, may submit `character.create`
through the gateway. The new character is an ordinary world character.
Refuse a second create for that viewer, and refuse every other command
from them. Leave Twitch, rate limits, and deduplication until that
create is real.
